## 0. 你将做出什么

一个 `ComfyUI-ModelLab` 包，包含 4 个可运行节点：

| 节点 ID | 干什么 |
|---|---|
| `PK_CheckpointLoader` | 加载 ckpt，可选是否输出 VAE / CLIP / 模型 |
| `PK_RegisterModels` | 模块导入时注册自定义模型目录，并提供一个从该目录选文件的节点 |
| `PK_LoraLoader` | 用 `comfy.sd.load_lora_for_models` 加载 LoRA 到模型与 CLIP |
| `PK_VAELoader` | 用 `comfy.sd.VAE(sd=...)` 从文件加载 VAE |

学完你会理解：一个 loader 节点本质是"读文件 → 调 `comfy.sd.*` 的加载函数 → 把 `ModelPatcher` / `CLIP` / `VAE` 对象返回"，以及模型目录是怎么被注册、被下拉框发现的。

---

## 1. 加载器节点到底返回什么

| 输出类型 | 实际 Python 对象 | 由谁产出 |
|---|---|---|
| `MODEL` | `ModelPatcher`（即 `model_patcher`） | `load_checkpoint_guess_config()[0]` / `load_diffusion_model()` |
| `CLIP` | `CLIP` 对象（内含 `.patcher`） | `load_checkpoint_guess_config()[1]` / `load_clip()` |
| `VAE` | `comfy.sd.VAE` 对象 | `comfy.sd.VAE(sd=...)` / `load_vae_patcher()` |
| `CLIP_VISION` | `CLIPVision` 对象 | `load_checkpoint_guess_config()[3]` |

**关键认知**：loader 节点只是把"文件"翻译成"运行时对象"。真正的权重加载、设备搬运、patch 应用都在 `comfy.sd.*` 里完成。你写的节点只做三件事：
1. 把 `ckpt_name`（下拉字符串）解析成绝对路径；
2. 调对应的 `comfy.sd.*` 加载函数；
3. 原样返回对象。

> ⚠️ **不要在你的节点里 `torch.load` 后自己搭模型**。直接复用 `comfy.sd` 的加载函数，否则会丢失 dtype 处理、dynamic 处理、multigpu 克隆等大量配套逻辑。

## 4. `PK_CheckpointLoader` —— 自定义 checkpoint 加载器

### 4.1 完整代码

```python
import comfy.sd
import folder_paths
from comfy_api.latest import io


class PK_CheckpointLoader(io.ComfyNode):
    @classmethod
    def define_schema(cls):
        return io.Schema(
            node_id="PK_CheckpointLoader",
            display_name="PK Checkpoint Loader",
            category="PK/loaders",
            description="Load a checkpoint, optionally skipping VAE/CLIP.",
            inputs=[
                io.Combo.Input("ckpt_name",
                               options=folder_paths.get_filename_list("checkpoints")),
                io.Boolean.Input("load_vae", default=True, advanced=True),
                io.Boolean.Input("load_clip", default=True, advanced=True),
            ],
            outputs=[
                io.Model.Output(),
                io.CLIP.Output() if True else io.CLIP.Output(),  # 占位，见下方说明
            ],
        )

    @classmethod
    def execute(cls, ckpt_name: str, load_vae: bool, load_clip: bool) -> io.NodeOutput:
        ckpt_path = folder_paths.get_full_path_or_raise("checkpoints", ckpt_name)
        model, clip, vae, _ = comfy.sd.load_checkpoint_guess_config(
            ckpt_path,
            output_vae=load_vae,
            output_clip=load_clip,
            output_clipvision=False,
        )
        return io.NodeOutput(model, clip, vae)
```

### 4.2 两个必须注意的点

1. **`outputs` 的槽位顺序必须和 `execute` 返回值一一对应**。上面 `outputs=[MODEL, CLIP, VAE]`，`execute` 返回 `io.NodeOutput(model, clip, vae)`。如果你把 `load_vae` 关掉，`vae` 会是 `None`，**仍然要返回**，不能省略槽位——否则连线契约错位。

2. **`options=folder_paths.get_filename_list("checkpoints")` 只在节点类被定义时求值一次**。新增文件后需要重启 ComfyUI 才能出现在下拉里（或用 `CUSTOM_DEV_TUTORIAL.md` 第 11 章的"刷新目录"路由）。`Combo.Input` 也支持 `options` 为可调用（若支持），否则用 `fingerprint_inputs`/`refresh` 机制（参考 `BUILTIN_NODES_GUIDE.md` 第 7 章 `PK_LoadPreset`）。

> 简化写法：上面的 `outputs` 直接写 `[io.Model.Output(), io.CLIP.Output(), io.VAE.Output()]` 即可（删掉那行占位的三元表达式，那是提醒你顺序要一致）。

## 5. `PK_RegisterModels` + 自定义目录

### 5.1 原理

`folder_paths.add_model_folder_path` 注册一个新目录。把它放在**模块顶层**（导入即执行），这样 ComfyUI 启动时目录就被登记，后续任何节点的 `get_filename_list` 都能看到。

### 5.2 完整代码

```python
import os
import folder_paths
from comfy_api.latest import io

# 模块导入时执行一次：注册自定义模型目录
_CUSTOM_DIR = os.path.join(folder_paths.models_dir, "PK-Models")
folder_paths.add_model_folder_path("PK-Models", _CUSTOM_DIR)
os.makedirs(_CUSTOM_DIR, exist_ok=True)   # 目录不存在会拖慢扫描，提前建好


class PK_RegisterModels(io.ComfyNode):
    """从一个自定义目录里选 checkpoint 加载。"""
    @classmethod
    def define_schema(cls):
        return io.Schema(
            node_id="PK_RegisterModels",
            display_name="PK Load From Custom Folder",
            category="PK/loaders",
            description="Load a checkpoint located in the registered PK-Models folder.",
            inputs=[
                io.Combo.Input("ckpt_name",
                               options=folder_paths.get_filename_list("PK-Models")),
            ],
            outputs=[io.Model.Output(), io.CLIP.Output(), io.VAE.Output()],
        )

    @classmethod
    def execute(cls, ckpt_name: str) -> io.NodeOutput:
        ckpt_path = folder_paths.get_full_path_or_raise("PK-Models", ckpt_name)
        model, clip, vae, _ = comfy.sd.load_checkpoint_guess_config(ckpt_path)
        return io.NodeOutput(model, clip, vae)
```

### 5.3 要点

- `folder_paths.models_dir` 是 `ComfyUI/models/` 的绝对路径，用它拼接能保证跨机器可移植。
- 目录名 `"PK-Models"` 是**你自定义的 folder_name**，不需要和内置重名；只要 `add_model_folder_path` 用了它，`get_filename_list("PK-Models")` 就能拿到文件。
- 想让 UI 实时刷新，参考 `CUSTOM_DEV_TUTORIAL.md` 第 11 章做 `/pk/models/refresh` 路由并清 `folder_paths.filename_list_cache`。

## 6. `PK_LoraLoader` —— 自定义 LoRA 加载器

### 6.1 原理

LoRA 不是"替换"模型，而是**给模型打补丁**。正确做法是：先 `load_torch_file` 读LoRA 的 state_dict，再调 `comfy.sd.load_lora_for_models(model, clip, lora_sd, ...)`，它会 `model.clone()` + `add_patches`，返回**新的** model/clip（原对象不被修改）。

### 6.2 完整代码

```python
import comfy.sd
import comfy.utils
import folder_paths
from comfy_api.latest import io


class PK_LoraLoader(io.ComfyNode):
    @classmethod
    def define_schema(cls):
        return io.Schema(
            node_id="PK_LoraLoader",
            display_name="PK Load LoRA",
            category="PK/loaders",
            description="Apply a LoRA to MODEL and CLIP via comfy.sd.load_lora_for_models.",
            inputs=[
                io.Model.Input("model"),
                io.CLIP.Input("clip"),
                io.Combo.Input("lora_name", options=folder_paths.get_filename_list("loras")),
                io.Float.Input("strength_model", default=1.0, min=-100.0, max=100.0, step=0.01, round=0.01),
                io.Float.Input("strength_clip", default=1.0, min=-100.0, max=100.0, step=0.01, round=0.01),
            ],
            outputs=[io.Model.Output(), io.CLIP.Output()],
        )

    @classmethod
    def execute(cls, model, clip, lora_name, strength_model, strength_clip) -> io.NodeOutput:
        lora_path = folder_paths.get_full_path_or_raise("loras", lora_name)
        lora_sd = comfy.utils.load_torch_file(lora_path, safe_load=True)
        new_model, new_clip = comfy.sd.load_lora_for_models(
            model, clip, lora_sd, strength_model, strength_clip,
        )
        return io.NodeOutput(new_model, new_clip)
```

### 6.3 要点

- **`load_lora_for_models` 内部已经帮你 clone**，所以你既可以返回新对象、也可以丢弃旧对象，原 `model`/`clip` 不受影响。这正是为什么 LoRA 节点能链式串多个。
- `safe_load=True` 用 `safetensors`/`torch` 的安全加载，避免 pickle 执行风险。
- 若要"旁路 LoRA"（不改权重、前向时叠加），用 `comfy.sd.load_bypass_lora_for_models`（源码同在 `comfy/sd.py:158` 附近），适合训练场景。
- 想给模型打**任意权重差**（不限于 LoRA 文件），用 `model_patcher.add_patches(patches_dict, strength_patch, strength_model)`，与 `CUSTOM_NODES_CONDITIONING_TUTORIAL.md` 的模型补丁思路一致。

## 7. `PK_VAELoader` / `PK_UNETLoader` —— 单独加载组件

### 7.1 VAE 加载器

直接沿用内置 `VAELoader.load_vae` 的写法（`nodes.py:69`）：

```python
import comfy.sd
import comfy.utils
import folder_paths
from comfy_api.latest import io


class PK_VAELoader(io.ComfyNode):
    @classmethod
    def define_schema(cls):
        return io.Schema(
            node_id="PK_VAELoader",
            display_name="PK Load VAE",
            category="PK/loaders",
            inputs=[
                io.Combo.Input("vae_name", options=folder_paths.get_filename_list("vae")),
            ],
            outputs=[io.VAE.Output()],
        )

    @classmethod
    def execute(cls, vae_name: str) -> io.NodeOutput:
        vae_path = folder_paths.get_full_path_or_raise("vae", vae_name)

        vae = comfy.sd.VAE(sd=sd, metadata=metadata)
        return io.NodeOutput(vae)
```

### 7.2 UNET / 扩散模型加载器

`load_unet` 已弃用，改用 `load_diffusion_model`（参考内置 `UNETLoader`，`nodes.py`）：

```python
class PK_UNETLoader(io.ComfyNode):
    @classmethod
    def define_schema(cls):
        return io.Schema(
            node_id="PK_UNETLoader",
            display_name="PK Load Diffusion Model",
            category="PK/loaders",
            inputs=[
                io.Combo.Input("unet_name", options=folder_paths.get_filename_list("diffusion_models")),
                io.Combo.Input("weight_dtype",
                               options=["default", "fp8_e4m3fn", "fp8_e4m3fn_fast", "fp8_e5m2"],
                               default="default", advanced=True),
            ],
            outputs=[io.Model.Output()],
        )

    @classmethod
    def execute(cls, unet_name: str, weight_dtype: str) -> io.NodeOutput:
        model_options = {}
        if weight_dtype == "fp8_e4m3fn":
            model_options["dtype"] = __import__("torch").float8_e4m3fn
        elif weight_dtype == "fp8_e5m2":
            model_options["dtype"] = __import__("torch").float8_e5m2
        elif weight_dtype == "fp8_e4m3fn_fast":
            model_options["dtype"] = __import__("torch").float8_e4m3fn
            model_options["fp8_optimizations"] = True
        unet_path = folder_paths.get_full_path_or_raise("diffusion_models", unet_name)
        model = comfy.sd.load_diffusion_model(unet_path, model_options=model_options)
        return io.NodeOutput(model)
```

## 9. 排错清单

| 现象 | 原因 | 解决 |
|---|---|---|
| 下拉里没有新文件 | 列表在类定义时只算一次 | 重启，或加刷新路由清 `filename_list_cache` |
| `RuntimeError: Could not detect model type` | ckpt 不是标准 checkpoint | 用 `Load Diffusers` 或确认文件完整 |
| LoRA 没效果 | 把 `strength` 写成 0 / 接错槽位 | `strength_model` 非 0；`model` 接 `[2,0]` |
| 显存爆了 | loader 默认不搬 GPU，但采样时才搬 | 用 `comfy.model_management.load_models_gpu([model])` 预载 |
| `add_model_folder_path` 无效 | 放到了 `execute` 里（每次执行才注册） | 放到**模块顶层**，导入即注册 |
| VAE 解码全黑/偏色 | 用了错配的 VAE | 确认 checkpoint 与 VAE 同架构（SD1.5 / SDXL / Flux） |

## 10. 进阶：把模型搬到 GPU 与权重补丁

### 10.1 预载到 GPU

```python
import comfy.model_management as mm
mm.load_models_gpu([model])   # 把模型权重搬到 load_device
```

采样节点内部会自动调它；但如果你在 loader 之后、采样之前做了大量 CPU 操作，预载可以避免重复搬运。

### 10.2 直接给模型打权重补丁（替代 LoRA 的通用手段）

```python
# model 是 ModelPatcher；patches: { "weight_key": tensor_delta }
new_model = model.clone()
applied = new_model.add_patches(patches_dict, strength_patch=1.0, strength_model=1.0)
if not applied:
    logging.warning("没有任何权重键匹配，补丁未生效")
```

`add_patches` 内部逻辑（`comfy/model_patcher.py:843`）：遍历 `patches` 字典，只给 `model.state_dict()` 里存在的 key 打补丁，返回实际生效的 key 集合。若返回空集，说明你的 key 与模型权重名不匹配（注意 UNET 权重的真实前缀，通常是 `diffusion_model.`）。
