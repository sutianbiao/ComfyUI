## 4. 执行引擎内部流程图

```
PromptExecutor.execute_async(prompt, prompt_id, extra_data)
       │
       ▼
┌──────────────────────────────────────────────────────────────┐
│ 1. 初始化阶段                                                  │
│   ├── set_preview_method()          设置预览方式               │
│   ├── nodes.interrupt_processing(False)  清除中断标志           │
│   ├── prompt_model_tracker.start()  开始追踪加载的模型          │
│   ├── server.client_id = extra_data["client_id"]               │
│   ├── add_message("execution_start", {prompt_id})              │
│   └── set_ram_cache_release_state()  配置 RAM 缓存释放         │
└──────────────────────────┬───────────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────────┐
│ 2. 构建 DynamicPrompt + 缓存初始化                              │
│   ├── DynamicPrompt(prompt)         从 JSON 构建 prompt 图      │
│   ├── reset_progress_state()        重置进度                    │
│   ├── IsChangedCache(...)           构建变更检测缓存             │
│   ├── for cache in caches.all:                                  │
│   │     await cache.set_prompt(dynamic_prompt, ...)            │
│   │     cache.clean_unused()            清理上次的缓存          │
│   └── 并发检查所有节点的缓存:                                     │
│       cache_results = await asyncio.gather(                    │
│         *(caches.outputs.get(node_id) for node_id in node_ids)│
│       )                                                        │
│       cached_nodes = [命中缓存的节点 ID 列表]                    │
└──────────────────────────┬───────────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────────┐
│ 3. 通知前端缓存命中情况                                          │
│   add_message("execution_cached", {nodes: cached_nodes})     │
└──────────────────────────┬───────────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────────┐
│ 4. 构建执行列表 (拓扑排序)                                       │
│   execution_list = ExecutionList(dynamic_prompt, caches, ...) │
│   从 OUTPUT_NODE 开始反向追溯，确定执行顺序                      │
│   for node_id in execute_outputs:                              │
│     execution_list.add_node(node_id)                           │
└──────────────────────────┬───────────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────────────┐
│ 5. 执行循环 (while not execution_list.is_empty())              │
│   │                                                           │
│   │  ┌─────────────────────────────────────────────────┐      │
│   │  │ node_id, error, ex = await execution_list        │      │
│   │  │   .stage_node_execution()                        │      │
│   │  │ 从执行列表中取出下一个节点                          │      │
│   │  └──────────────────┬──────────────────────────────┘      │
│   │                     │                                      │
│   │          ┌──── error? ────┐                               │
│   │          │                │                                │
│   │          ▼ No error       ▼ Has error                      │
│   │  ┌───────────────┐  ┌───────────────────┐                 │
│   │  │ execute(...)  │  │ handle_execution_ │                 │
│   │  │ (见第 5 节)   │  │   error()         │                 │
│   │  │               │  │ break             │                 │
│   │  └───────┬───────┘  └───────────────────┘                 │
│   │          │                                                 │
│   │    ┌─────┴─────┬───────────┐                              │
│   │    │           │           │                              │
│   │    ▼ FAILURE   ▼ PENDING   ▼ SUCCESS                      │
│   │  handle_error  unstage     complete_node_execution()      │
│   │  break         (重新等待)                                    │
│   │                                                           │
│   │  ┌─────────────────────────────────────────────────┐      │
│   │  │ RAM 压力检查 (仅 cache_type == RAM_PRESSURE):    │      │
│   │  │   ram_release_callback(ram_inactive_headroom)   │      │
│   │  │   if ram_shortfall > 0:                          │      │
│   │  │     freed = ram_release_callback(ram_headroom,   │      │
│   │  │              free_active=True)                   │      │
│   │  │   if should_free_pins:                          │      │
│   │  │     free_pins(ram_shortfall)  ← 释放固定内存     │      │
│   │  └─────────────────────────────────────────────────┘      │
│   │                                                           │
│   └───────────────────────────────────────────────────────┘  │
│                          │                                      │
│                    ┌─────┴─────┐                               │
│                    │           │                               │
│                 正常完成      中断/错误                          │
│                    │           │                               │
│                    ▼           ▼                               │
```

```
       │           │      │  执行: CLIP.encode(text)
       │           │      │  输出: CONDITIONING (正面)

       │                  │  执行: CLIP.encode(text)
       │                  │  输出: CONDITIONING (负面)
       │                  │
       │                  └──→ CONDITIONING ──→ [3] KSampler.negative
       │

       │  输入: width=512, height=512, batch_size=1

       │

       │  输入: model, seed, steps=20, cfg=8.0,
       │        sampler_name="euler", scheduler="normal",
       │        positive, negative, latent_image, denoise=1.0
       │

       │    1. prepare_noise(latent, seed)

       │    3. calculate_sigmas(steps, scheduler)

```

```
  [10] LoadImage
       │  输入: image = "input.png"
       │  执行: 读取图片 → torch.Tensor [B,H,W,3]
       │  输出: IMAGE
       │
       └──→ IMAGE ──→ [11] VAEEncode
                        │  输入: pixels=IMAGE, vae=VAE
                        │  执行: VAE.encode(image)
                        │         ├── 卷积编码
                        │         └── 返回 [B, C, H/8, W/8]
                        │  输出: LATENT (已编码的图像)
                        │
                        └──→ LATENT ──→ [3] KSampler.latent_image

  [4] CheckpointLoaderSimple
       ├──→ MODEL, CLIP, VAE
       │         │
       │         └──→ VAE ──→ [11] VAEEncode.vae
       │
       ├──→ CLIP ──→ [6] CLIPTextEncode(正面) ──→ CONDITIONING
       └──→ CLIP ──→ [7] CLIPTextEncode(负面) ──→ CONDITIONING

  [3] KSampler
       │  关键区别: denoise = 0.5 (而非 1.0)
       │  denoise < 1.0 时:
       │    ├── 不是从纯噪声开始
       │    ├── 将噪声添加到现有 latent (部分加噪)
       │    └── 保留原始图像的结构信息
       │
       │  prepare_noise + latent → noisy_latent
       │  noisy_latent = latent + noise * sigma[0] * denoise
       │
       │  然后执行正常去噪循环 (steps * denoise 步)
       │
       └──→ LATENT ──→ [8] VAEDecode ──→ IMAGE ──→ [9] SaveImage

  [4] → [10] → [11], [6], [7] → [3] → [8] → [9]

  ┌────────────────┬──────────────────┬──────────────────┐
  │                │ 文生图 (txt2img)  │ 图生图 (img2img)  │
  ├────────────────┼──────────────────┼──────────────────┤
  │ 初始 latent    │ EmptyLatentImage  │ LoadImage →       │
  │                │ (全零)            │ VAEEncode         │
  │ denoise        │ 1.0              │ 0.3 ~ 0.7         │
  │ 加噪方式       │ 从纯噪声开始      │ 部分加噪           │
  │ 保留原图结构   │ 否               │ 是 (denoise 越低   │
  │                │                  │ 保留越多)          │
  └────────────────┴──────────────────┴──────────────────┘
```

## 15. 内置工作流模板 — LoRA 加载数据流图

```
LoRA (Low-Rank Adaptation) 加载工作流:

  [4] CheckpointLoaderSimple
       │  输出: MODEL, CLIP, VAE
       │
       ├──→ MODEL ──→ [14] LoraLoader.model
       ├──→ CLIP  ──→ [14] LoraLoader.clip
       │
       │
  [14] LoraLoader
       │  输入: model=MODEL, clip=CLIP,
       │        lora_name="style.safetensors",
       │        strength_model=0.8,
       │        strength_clip=0.8
       │
       │  执行:
       │    comfy.lora.load_lora(lora_path)
       │    ├── 读取 LoRA safetensors 文件
       │    ├── 解析 key_lora (UNet/CLIP 分别处理)
       │    │
       │    │  对 model:
       │    │    model_patcher.calculate_weight(lora_patches,
       │    │      current_weight, key)
       │    │    ├── 对每个匹配的权重:
       │    │    │   up = lora_up @ lora_down  (低秩矩阵乘)
       │    │    │   new_weight = old_weight + up * strength
       │    │    │   (通过 hooks 系统，不修改原始权重)
       │    │    └── 返回 patch 后的 model_patcher
       │    │
       │    │  对 clip:
       │    │    类似处理 CLIP 模型权重
       │    │
       │    └── 返回 patched MODEL, patched CLIP
       │
       │  输出: MODEL (带 LoRA patch), CLIP (带 LoRA patch)
       │
       ├──→ MODEL (patched) ──→ [3] KSampler
       └──→ CLIP (patched)  ──→ [6] CLIPTextEncode
                                   → CONDITIONING ──→ [3] KSampler

拓扑执行顺序:
  [4] → [14] → [6], [7] → [3] → [8] → [9]

LoRA 权重计算原理:
  原始权重: W ∈ R^(d×d)
  LoRA 分解: W + α × (B @ A), 其中 B ∈ R^(d×r), A ∈ R^(r×d), r << d
  strength_model = α (缩放因子)

  通过 hooks 系统 (comfy/hooks.py) 实现:
  ┌──────────────────────────────────────────┐
  │ WeightHook 注册到 ModelPatcher           │
  │   ├── 不修改原始参数 (内存高效)           │
  │   ├── 在 forward 时动态计算 patch         │
  │   └── 支持多个 LoRA 叠加 (HookGroup)     │
  └──────────────────────────────────────────┘

多 LoRA 级联:
  [4] Checkpoint → [14a] LoraLoader(strength=0.8)
                    → [14b] LoraLoader(strength=0.5)
                      → [14c] LoraLoader(strength=1.0)
                        → MODEL (三个 LoRA 叠加效果)
```

```
│    执行上游节点链 → 获得 on_true 的值             │
│    on_false 的上游被跳过 (节省计算/显存)          │
└──────────────────────┬───────────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────────┐
│ 4. 再次调用 check_lazy_status                    │
│    switch=True, on_true=Tensor, on_false=None   │
│    on_true 已就绪 → 不再需要                     │
│    on_false 不需要 (switch=True)                 │
│    返回 [] (空列表)                              │
└──────────────────────┬───────────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────────┐
│ 5. 所有需要的输入已就绪                           │
│    调用 execute(switch=True, on_true=Tensor)    │
│    on_false=None (被跳过)                       │
│    返回结果                                       │
└──────────────────────────────────────────────────┘

ExecutionBlocker 流程:
┌──────────────────────────────────────────────────┐
│ 节点返回 ExecutionBlocker(None)                  │
│    │                                             │
│    ▼                                             │
│ 下游节点收到 ExecutionBlocker                    │
│    │                                             │
│    ├── 跳过执行                                   │
│    ├── 将 ExecutionBlocker 传递给更下游           │
│    └── (无法停止传播)                             │
│                                                  │
│ 节点返回 ExecutionBlocker("error message")      │
│    │                                             │
│    ▼                                             │
│ 下游节点收到 → 显示错误消息                       │
│ "error message"                                  │
└──────────────────────────────────────────────────┘
```

## 附录: 图表术语对照

| 术语 | 英文 | 说明 |
|---|---|---|
| 节点 | Node | 工作流的基本单元，执行特定操作 |
| 工作流 | Workflow / Prompt | 节点组成的有向无环图 |
| 拓扑排序 | Topological Sort | 按依赖关系排序节点执行顺序 |
| 潜空间 | Latent | 压缩后的特征表示，通常是图像的 1/8 |
| 条件 | Conditioning | 文本编码后的条件向量 |
| 采样 | Sampling | 在潜空间中逐步去噪的过程 |
| CFG | Classifier-Free Guidance | 无分类器引导，平衡正负条件 |
| LoRA | Low-Rank Adaptation | 低秩适配，轻量模型微调 |
| ControlNet | — | 条件控制网络，引导生成方向 |
| VAE | Variational Autoencoder | 变分自编码器，潜空间与像素空间转换 |
| ModelPatcher | — | 模型包装器，支持权重补丁 |
| AIMDO | — | 异步权重流式传输设备卸载 |
| Hook | — | 钩子，不改核心代码影响模型行为 |
| Lazy Evaluation | 懒求值 | 延迟评估不需要的输入 |
| ExecutionBlocker | — | 阻断下游节点执行的对象 |
| RAMPressureCache | — | 基于 RAM 压力的缓存策略 |
| comfy-kitchen | — | ComfyUI 的优化算子库 |
| comfy-aimdo | — | ComfyUI 的设备卸载库 |
