## 1. 架构总览

ComfyUI 采用分层架构,从上到下分为六层:

```
┌─────────────────────────────────────────────────────────┐
│                    前端 (Frontend)                        │
│          comfyui-frontend-package (Vue/TS)               │
│               通过 PyPI 分发,独立仓库                      │
├─────────────────────────────────────────────────────────┤
│              服务器层 (Server Layer)                      │
│   server.py — PromptServer (aiohttp Web Server)          │
│   main.py — 入口与初始化                                   │
├─────────────────┬───────────────────────────────────────┤
│   应用服务层     │           执行引擎层                     │
│   app/          │    execution.py — PromptExecutor        │
│   app/assets/   │    comfy_execution/ — 图、缓存、任务     │
├─────────────────┴───────────────────────────────────────┤
│                   节点系统 (Node System)                  │
│   nodes.py — 65 个内置节点                                │
│   comfy_extras/ — 142 个扩展节点文件                       │
│   comfy_api_nodes/ — 41 个合作方 API 节点                 │
├─────────────────────────────────────────────────────────┤
│              核心引擎层 (Core Engine)                     │
│   comfy/ — 模型管理、采样、算子、量化、内存、钩子           │
├─────────────────────────────────────────────────────────┤
│              模型实现层 (Model Implementations)           │
│   comfy/ldm/ — 50+ 模型族实现                             │
│   comfy/text_encoders/ — 56 个文本编码器                  │
│   comfy/cldm/ — ControlNet                              │
└─────────────────────────────────────────────────────────┘
```

## 2. 分层职责

### 入口层
**`main.py`** (630 行) — 程序入口,负责:
- 解析命令行参数(`comfy/cli_args.py`)
- 初始化 CUDA malloc(`cuda_malloc.py`)
- 加载自定义路径(`extra_model_paths.yaml`)
- 执行预启动脚本(custom_nodes 中的 `__init__.py`)
- 启动 PromptServer 与 prompt_worker(执行队列消费者)
- 初始化数据库与资产系统

### 服务器层
**`server.py`** (1,568 行) — `PromptServer` 类,基于 aiohttp:
- WebSocket 实时通信(`/ws`)
- 静态前端文件服务(`/`)
- 模型/扩展查询、图片上传/查看、系统状态
- Prompt 队列管理(`/prompt`、`/queue`、`/interrupt`)
- 历史记录(`/history`)
- 任务 API(`/api/jobs`)
- 中间件:CORS、压缩、离线 CSP、源限制

### 执行引擎层
**`execution.py`** (1,464 行) — `PromptExecutor` 类:
- 接收 prompt 图,执行拓扑排序
- 逐节点执行,管理输入/输出数据传递
- 维护执行缓存(部分图重执行)
- 错误处理与结果合并

**`comfy_execution/`** (2,749 行) — 执行支持模块:
- `graph.py` — `DynamicPrompt`、`ExecutionList`(拓扑排序)
- `caching.py` — 多种缓存策略(RAMPressure、LRU、Hierarchical、Null)
- `jobs.py` — 任务状态规范化与查询
- `progress.py` — 执行进度跟踪
- `cache_provider.py` — 缓存提供者接口
- `graph_utils.py` — 图工具函数
- `validation.py` — 图验证

### 节点系统
**`nodes.py`** (2,628 行) — 65 个核心内置节点,包括:
- CheckpointLoaderSimple、VAELoader、CLIPTextEncode
- KSampler、VAEDecode、VAEEncode、SaveImage
- LoadImage、EmptyLatentImage、LatentUpscale
- Conditioning 组合节点

**`comfy_extras/`** (142 个文件) — 扩展节点,按功能分类:
- 模型加载与合并、采样器与调度、条件操作
- 图像处理、掩码操作、合成与混合
- 视频模型、音频生成、3D 生成
- ControlNet、LoRA、Hypernetwork
- 数学运算、逻辑、字符串处理

### 核心引擎层 (comfy/)
模型管理、采样、算子选择、量化、内存管理的核心(详见[第 4 节](#4-核心引擎层-comfy))。

### 模型实现层 (comfy/ldm/)
50+ 个模型族的 PyTorch 实现(详见[第 5 节](#5-模型实现层-comfyldm))。

## 7. 执行引擎

### 7.1 执行流程

```
用户提交 Prompt (POST /prompt)
        │
        ▼
PromptServer.add_routes() → /prompt handler
        │  解析 JSON,构建 DynamicPrompt
        │  调用 on_prompt handlers
        ▼
PromptQueue.put(prompt)  ← 队列管理
        │
        ▼
prompt_worker()  ← main.py 中的消费者循环
        │
        ▼
PromptExecutor.execute(prompt)
        │  1. 构建 ExecutionList (拓扑排序)
        │  2. 遍历节点,逐个执行
        │  3. 对每个节点:获取输入数据 → 调用节点函数 → 存储输出
        │  4. 检查缓存:只执行变化的部分
        │  5. 错误处理与结果合并
        ▼
返回结果 → 保存到 history → WebSocket 通知前端
```

### 7.2 执行引擎模块

| 文件 | 关键类 | 职责 |
|---|---|---|
| `execution.py` | `PromptExecutor`, `PromptQueue`, `CacheSet`, `IsChangedCache` | 节点图执行主循环、缓存管理 |

| `comfy_execution/caching.py` | `RAMPressureCache`, `LRUCache`, `HierarchicalCache`, `NullCache`, `BasicCache` | 多策略缓存(RAM 压力/LRU/层级/无缓存) |
| `comfy_execution/jobs.py` | `JobStatus`, `normalize_queue_item`, `normalize_history_item` | 任务状态规范化 |
| `comfy_execution/progress.py` | — | 执行进度跟踪 |
| `comfy_execution/validation.py` | — | 图验证 |
| `comfy_execution/cache_provider.py` | — | 缓存提供者接口 |

### 7.3 缓存策略

| 策略 | CLI 参数 | 行为 |
|---|---|---|
| RAMPressureCache(默认) | `--cache-ram` | 基于系统 RAM 压力自动驱逐,active/inactive 双阈值 |
| LRU | `--cache-lru N` | 最多缓存 N 个节点结果 |
| HierarchicalCache | `--cache-classic` | 旧式激进缓存 |
| NullCache | `--cache-none` | 不缓存,每次全量执行 |

## 11. 数据流:从 Prompt 到图像

以下是一个典型的文生图工作流从提交到输出的完整数据流:

```
1. 用户在前端构建工作流图,点击 Queue → POST /prompt
   │
   ├── JSON 包含:节点定义、连线关系、参数值、extra_data
   │
2. PromptServer /prompt handler
   │  ├── 验证图结构
   │  ├── 调用 on_prompt handlers(hooks, custom_nodes)
   │  └── 入队 PromptQueue
   │
3. prompt_worker (main.py)
   │  └── PromptExecutor.execute(prompt)
   │       ├── 构建 ExecutionList (comfy_execution/graph.py 拓扑排序)
   │       ├── 检查缓存(caching.py),只执行变化部分
   │       └── 遍历节点:
   │
4. 节点执行顺序(以文生图为例):
   │  (1) CheckpointLoaderSimple
   │       └── comfy.sd.load_checkpoint_guess_config()
   │           ├── comfy.model_detection.detect_unet_config() ← 从 state_dict 反推配置
   │           ├── comfy.supported_models 匹配模型族
   │           ├── 构建 BaseModel (comfy.model_base)
   │           ├── 包裹为 ModelPatcher (comfy.model_patcher)
   │           └── comfy.model_management 注册 LoadedModel
   │
   │  (2) CLIPTextEncode (正/负提示词)
   │       └── CLIP 模型编码文本 → conditioning 对象
   │
   │  (3) EmptyLatentImage
   │       └── 创建空潜空间张量 [B, C, H, W]
   │
   │  (4) KSampler
   │       └── comfy.sample.sample()
   │           ├── prepare_noise() — 生成噪声
   │           ├── comfy.samplers.sampling_function()
   │           │   ├── calc_cond_batch() — 批量条件计算
   │           │   ├── cfg_function() — CFG 引导
   │           │   ├── model_model_patcher 计算模型(权重在 GPU)
   │           │   │   └── model_management.load_models_gpu() — 加载到 GPU
   │           │   └── 循环 N 步去噪
   │           │       ├── comfy.samplers.KSAMPLER.sample()
   │           │       └── 每步:model(x, t, c) → BaseModel.forward()
   │           │           └── transformer_blocks → attention → comfy.ops
   │           └── 返回去噪后的 latent
   │
   │  (5) VAEDecode
   │       └── VAE.decode(latent) → 像素图像 [B, H, W, 3]
   │
   │  (6) SaveImage
   │       └── 保存 PNG(含工作流元数据)
   │
5. 结果返回:
   │  ├── 存入 history
   │  ├── WebSocket 推送执行完成事件
   │  └── 前端显示生成图像
```

### 关键路径中的模型加载

```
CheckpointLoaderSimple
  └── comfy.sd.load_checkpoint_guess_config(filepath)
        ├── comfy.utils.load_torch_file() ← 读 safetensors/ckpt
        ├── comfy.model_detection.model_config_from_unet()
        │     ├── detect_unet_config(state_dict) ← 探测 depth/dim/heads
        │     └── 匹配 supported_models 中的模型族
        ├── model_config.get_model(state_dict)
        │     └── BaseModel.__init__() ← 构建 PyTorch 模型
        │           └── operations = comfy.ops.pick_operations() ← 选择算子策略
        ├── comfy.model_patcher.ModelPatcher(model)
        │     └── 包装模型,支持 hooks/patches/lazy-load
        └── comfy.model_management.register_loaded_model()
              └── 跟踪 VRAM 占用,管理卸载
```
